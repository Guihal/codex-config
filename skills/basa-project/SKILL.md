# basa → новый проект

Шаблон: `https://github.com/Guihal/basa` (публичный; ssh-зеркало
`git@github.com:Guihal/basa.git`). Стек: Vite 7 + TS + SCSS, pnpm, vitest.
Результат — рабочий чекаут конкретного проекта, а не копия демо.

## Правила исполнения

projects_root: <агент вписывает сюда фактический путь; пустое = спросить>

1. Не выдумывай путь: пока `projects_root` пуст и бриф не дал ответа, шаг 1 не начинается.
2. Ничего не удаляй из шаблона, кроме явно перечисленного в
   `references/adapt-checklist.md`.
3. Tilda-контракт обязателен и не зависит от того, упомянул ли его человек —
   см. `references/tilda-rules.md`.
4. Отчёт в конце — по-русски, с готовым сниппетом вставки.

## Шаг 0 — папка проектов (блокирующий)

Откуда берётся путь, по порядку:

1. строка `projects_root:` в этом файле — если заполнена, использовать её и не спрашивать;
2. `projects_root` в `~/.codex/PERSON.md` или в блоке `<!-- profile:start -->` файла `AGENTS.md`
   (туда его пишет скилл брифа);
3. если нигде нет или стоит `declined` — спросить одним вопросом:
   **«Где лежат папки проектов? Дай абсолютный путь.»**

Получив путь, **сразу вписать его в этот файл** — заменить плейсхолдер в строке `projects_root:`,
чтобы следующие запуски не спрашивали. Если каталога нет — не создавать молча: показать и спросить.
Не подставлять `~/projects`, `~/dev` или текущий каталог.

## Шаг 1 — параметры проекта

Собери одним блоком (человек может ответить частично; недостающее — уточни один раз):

- slug — значение `name` в `package.json` (каталог проекта называется по названию проекта);
- название проекта/клиента;
- платформа: Tilda / WordPress / другое;
- страницы и блоки в первом объёме работ;
- язык сайта;
- нужна ли логика Tilda Store (избранное, связанные цвета, корзина).

Если платформа Tilda, но неизвестна страница или блок — не пиши код «по
представлению»: попроси URL страницы или id блока (см. `references/tilda-rules.md`).

## Шаг 2 — чекаут

```bash
git clone https://github.com/Guihal/basa.git "<projects_root>/<название>"
# если https требует авторизации:
git clone git@github.com:Guihal/basa.git "<projects_root>/<название>"
```

Каталог проекта называется **по названию проекта**, а не по слову `basa`: в `projects_root`
лежит папка конкретного проекта. `slug` для `package.json` берётся из этого названия
(латиница без пробелов); если человек дал готовый slug — использовать его.

Прежде чем клонировать:

- если `<projects_root>/<название>` существует — остановись и спроси: переиспользовать
  существующий каталог или взять другое имя;
- если существует другой чекаут того же проекта — предложи его, не создавай второй.

`cd "<projects_root>/<название>"` и дальше работай только внутри него.

## Шаг 3 — подрезка под проект

Полный список файлов — `references/adapt-checklist.md`. Обязательный минимум:

1. `package.json`: `name` = slug, `description` = название проекта; добавь скрипт
   `build:pages` с явным списком страниц, потому что `PAGES` читается только из
   `process.env` и нигде не сохраняется: `"build:pages": "PAGES=index,<pages> vite build"`
   (для одной страницы достаточно `pnpm build`).
2. `README.md`: имя проекта, команды, состав страниц. Демо-описание шаблона убрать.
3. `src/js/main.ts` и `src/scss/main.scss`: первый реальный блок проекта вместо пустого шаблона.
4. `docs/refactor/**` (23 документа рефакторинга шаблона) — удалить, они не про проект.
5. Удали демонстрационные записи, которых нет в проекте; не удаляй `src/js/utils/**`,
   SCSS-систему (`_vars`, `_mixins`, `_functions`, `utils/`), `vite.config.ts`,
   `vitest.config.ts`, `tests/**`.

## Шаг 4 — Tilda-контракт

Прочитай `references/tilda-rules.md` целиком и следуй ему. Ключевое:

- только инлайн-скрипты и стили, никаких внешних фреймворков и CDN;
- сначала изучи реальные скрипты страницы (data-атрибуты, recordType блоков, id),
  потом код;
- итог отдаётся как ES-модуль и вставляется в Tilda через `<script type="module">`;
  смысл — изолированная область видимости и отсутствие конфликтов переменных;
- в отчёте человеку всегда есть строка-напоминание про `type="module"`.

## Шаг 5 — проверка

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

Ожидаемо: установка проходит (allowBuilds учтён в `package.json`), сборка даёт
`app/index.html` и `app/css/index.css` (плюс `app/js/*` при непустом `main.ts`),
тесты зелёные. Если сборка падает на отсутствующем `$colors` или `$size-vars` —
это известное состояние шаблона (см. «Известные проблемы» в `AGENTS.md`), реши
под проект, а не глуши ошибку.

## Шаг 6 — отчёт

Коротко, по-русски:

- что переименовано и что удалено;
- какие команды запускались и чем закончились;
- готовый сниппет для Tilda:

```html
<script type="module">
  // содержимое сборки app/js/<name>.js или ссылка на него
</script>
```

- напоминание: **скрипты вставляются в Tilda как `type="module"`** — ради изоляции:
  переменные и функции скрипта не попадают в глобальный scope страницы и не конфликтуют
  с другими скриптами Tilda;
- что осталось сделать (страницы, контент, интеграции).
