# Tilda-контракт

Обязательные правила для любой работы, которая касается Tilda. Действуют по
умолчанию, без отдельного напоминания от человека.

## 1. Только инлайн

- Скрипты и стили живут в проекте и вставляются в страницу Tilda инлайном.
- Никаких внешних фреймворков, CDN-подключений и новых рантайм-зависимостей.
  Единственная допустимая runtime-зависимость шаблона — `ts-debounce`.
- Всё, что можно выразить средствами шаблона (утилиты `src/js/utils/**`,
  SCSS-система), выражается ими, а не новой библиотекой.

## 2. Сначала изучай реальные скрипты страницы

Перед первой строкой кода:

- открой страницу Tilda и посмотри, какие скрипты и блоки там уже есть;
- определи `recordType` блоков, с которыми работаешь (в шаблоне уже
  обрабатываются `396, 131, 702, 985, 978, 451, 1002, 706`);
- собери фактические `data-*`-атрибуты, id и классы, на которые можно опереться;
- проверь, не решает ли задачу существующий модуль (`setAutoscale`, `setZoom`,
  `moveTabs`, `linkedColors`, `favoriteProducts`).

Без этих данных структура блока неизвестна: попроси URL страницы или id блока у
человека вместо догадок.

## 3. Вставка — `<script type="module">`

- Сборка отдаёт ES-модуль; в Tilda он вставляется как
  `<script type="module">…</script>` (или `<script type="module" src="…">`).
- Зачем: модуль даёт **изолированную область видимости**. Переменные и функции
  скрипта не попадают в глобальный `window` страницы и не конфликтуют с другими
  скриптами Tilda, её блоками и чужими вставками. Побочно доступны `import` и
  top-level `await`.
- Чего это не даёт: `type="module"` не делает код корректным сам по себе —
  сборка обязана быть валидным ES-модулем, а изоляция не отменяет проверку
  синтаксиса и поведения.
- В каждом отчёте человеку — отдельная строка про изоляцию и сниппет вставки.
  Человек вставляет код руками, и это самое частое место ошибки.

## 4. Границы Tilda-слоя

- `src/js/tilda/` — для тильда-специфичной бизнес-логики (связанные цвета,
  избранное, автозум). Простой скрипт для одной страницы может лежать прямо в
  `src/js/` — структура папок ориентир, а не закон.
- `tilda/index.ts` — barrel, не импортируется в `main.ts` автоматически.
  Многостраничность — через `PAGES` (см. `build:pages`).
- Tilda Store: запросы к `store.tildaapi.ru` — через существующую обёртку
  `favoriteProducts/data/tildaFetch.ts`, без прямых `fetch` по месту.
- Автомасштаб — через CSS `zoom` (`setAutoscale*`), а не трансформами.

## 5. Проверка результата

- `pnpm build` проходит, `app/` содержит ожидаемые артефакты;
- `pnpm test` зелёный (27 тестов на чистом шаблоне);
- в браузере проверен реальный сценарий блока на живой странице, если человек
  дал доступ;
- в отчёте есть сниппет вставки с `type="module"`.
